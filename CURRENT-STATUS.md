# Current Status

Vellum Rift is at the start of the project.

This repository currently represents an early project-foundation and ideation workspace rather than a mature implementation repository. The purpose of the current state is to let the team align on product direction, architecture, onboarding, vocabulary, and local development setup before heavier feature delivery begins.

## What Exists Today

- a documented product vision and early architectural direction
- governance, compliance, onboarding, and planning documents
- a local infrastructure scaffold for Postgres, Hasura, MinIO, and tooling
- a backend scaffold in `backend/`
- a WebRTC SFU scaffold in `webrtc-sfu/`
- a Vite and React dashboard scaffold in `web-dashboard/`
- an existing Unity project in `vr-client-unity/Vellum Rift`
- a speech-service orchestration scaffold for Faster-Whisper and Piper

## What Does Not Exist Yet

- a production-ready backend implementation
- a production-ready WebRTC SFU implementation
- a completed dashboard application
- finalized migration tooling
- completed Piper synthesis integration
- finalized team ownership assignments or operating roles

## Team Status

The team has not formally assigned roles yet.

That means the current documentation should be read as support for ideation and early contribution, not as a rigid org chart. Documents that describe backend, frontend, XR, or planning starting points are intended to help people orient themselves by discipline, not to imply that responsibility assignments are already fixed.

## Primary Goal Right Now

The current goal is to help the team ideate effectively with shared context.

That includes:

- agreeing on vocabulary
- aligning on architectural boundaries
- understanding the local development environment
- reducing ambiguity about product direction
- making it easy for contributors to explore the repo without tribal knowledge

## Working Expectation

During this phase, lightweight scaffolds and strong docs are acceptable so long as they make the next implementation decisions clearer. The team should prefer clarity, traceability, and shared understanding over premature completeness.
